# 防逆向工程方案

> 目标：让 APK / EXE 里的图片、AssetBundle 和代码不能“拖进工具就整包导出”。
> 先说结论：**离线分发的客户端不存在绝对防解包**。本方案做的是把破解成本从“双击 AssetStudio”提高到“需要逆算法、转储内存、Hook 运行时”，并让篡改行为可被发现。

---

## 一、这些工具是怎么工作的

### 1. 代码

| 工具 | 原理 | 对应反制 |
| --- | --- | --- |
| dnSpy / ILSpy / de4dot | Mono 后端会把 C# 编译成 `Assembly-CSharp.dll`，这些工具可直接反编译、调试、去混淆 | 切换到 **IL2CPP** 后端，不发布托管 DLL |
| Il2CppDumper | 解析 `libil2cpp.so` + `global-metadata.dat`，还原类名、方法签名，生成 `dump.cs` 和 IDA/Ghidra 脚本 | IL2CPP + 名称混淆 + **global-metadata 加密/加固**（需引擎或加固厂商支持，纯 C# 做不到） |
| Cpp2IL / CPP2IL | 从 IL2CPP 二进制中恢复 IL，输出更接近源码的工程 | 同上；再加原生层反调试与完整性校验 |
| Frida / Xposed / Zygisk | 运行时注入，Hook 解密函数、直接读内存 | 本方案的 maps 特征扫描、TracerPid、27042 端口探测；只能提高门槛 |
| Cheat Engine / GameGuardian | 运行时改内存、dump 内存中的贴图与资源 | 贴图 `Apply(false, true)` 设为不可读、按需解密、不长期保留明文 |

关键点：**IL2CPP 只是把“反编译源码”变成“反编译伪代码”**，`global-metadata.dat` 仍然包含全部类名、方法名和字符串，所以 Il2CppDumper 依旧能生成可读的 `dump.cs`。要真正对抗它，必须使用引擎级的 metadata 加密或商业加固。

### 2. 资源

AssetStudio、AssetRipper、UABEA 并不“破解加密”，它们只是按 Unity 公开的序列化格式解析：

1. 读取文件头，识别 `UnityFS` / `SerializedFile` / 版本号；
2. 按类型树（TypeTree）解析对象表；
3. 把贴图、音频、模型、场景对象导出为 PNG / WAV / FBX / Prefab。

所以最有效的资源防护不是“改贴图格式”，而是**让文件头不再是 Unity 能识别的格式**：构建时用自定义容器包裹并加密，运行时先在内存里解密，再交给 Unity 加载。Unity 官方的 “Content Protection” 文档也明确说：加密只能提高破解难度，不能做到绝对安全。

### 3. 安装包与运行时

- Android 重签名/二次打包：`Application.genuine` + 读取 APK 签名证书 SHA-256 对比。
- 调试器附着：`/proc/self/status` 的 `TracerPid`、托管调试器检测。
- 注入框架：`/proc/self/maps` 中的 `frida`、`gadget`、`xposed`、`zygisk`、`lsposed`、`riru` 等特征。
- 资源被替换：对每个加密文件记录 SHA-256，清单本身再用 HMAC 保护，改文件或改清单都会被发现。

## 二、本方案包含什么

```
Assets/防逆向工程/
├─ 说明.md
├─ 运行时/
│  ├─ 安全配置.cs        总开关：签名指纹、响应方式、检测间隔
│  ├─ 密钥仓库.cs        还原主密钥、派生 AES / HMAC 子密钥
│  ├─ 加密文件格式.cs    LFLN 容器：AES-256-CBC + HMAC-SHA256
│  ├─ 加密资源.cs        同步 / 协程加载图片、Sprite、AssetBundle
│  ├─ 完整性校验.cs      Application.genuine、APK 签名、资源清单
│  ├─ 反调试检测.cs      后台线程检测 Frida / Xposed / 调试器
│  └─ 安全核心.cs        自动启动，汇总检测并按配置响应
├─ 生成/
│  └─ 密钥数据.生成.cs   由菜单生成，保存拆分的密钥
└─ Editor/
   ├─ 密钥生成器.cs      菜单：防逆向/生成新密钥
   ├─ 资源加密工具.cs    菜单：防逆向/加密资源工具
   └─ 构建后处理.cs      构建后检查后端、密钥、签名配置
```

### 加密文件格式（LFLN）

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | 魔数 `LFLN`（不是 `UnityFS`） |
| 4 | 1 | 版本 |
| 5 | 1 | 标志（1 = AES-256-CBC + PKCS7） |
| 6 | 2 | 保留 |
| 8 | 16 | 随机 IV |
| 24 | 32 | HMAC-SHA256（Encrypt-then-MAC） |
| 56 | 剩余 | AES 密文 |

- AES 密钥与 HMAC 密钥由主密钥经 HMAC-SHA256 按用途派生，互不复用。
- 校验失败直接抛异常，不会把损坏数据交给 Unity。
- 文件被替换、截断、拼接都会在解密前失败。

### 密钥拆分

主密钥不直接写入源码，而是：

```
片段甲 = 主密钥 XOR 随机掩码
片段乙 = 随机掩码
```

两份都按字节反序保存为十六进制常量，运行时异或还原。这能避免密钥以明文出现在字符串表和搜索结果里，但**不能阻止内存转储**——离线解密必然要把密钥带在客户端上。

## 三、使用步骤

### 1. 打开必要的 Player Settings

- Scripting Backend：**IL2CPP**
- Android：Target Architectures 至少勾选 **ARM64**
- Managed Stripping Level：**High**（如果项目大量使用反射，先降到 Medium 并实测）
- 不要勾选 “Development Build”

### 2. 生成密钥

菜单 `防逆向/生成新密钥`。会生成：

- `Assets/防逆向工程/密钥~/主密钥.bin`（Unity 忽略此目录，**必须 gitignore**）
- `Assets/防逆向工程/生成/密钥数据.生成.cs`

换密钥会导致旧加密资源全部失效，需要重新加密。

### 3. 加密素材

菜单 `防逆向/加密资源工具`：

1. 源资源：在 Project 窗口多选文件夹或单个素材，点击“添加 Project 选中项”，也可以直接拖进窗口；每项可单独移除。
2. 源列表为空时，会递归加密“源为空时加密”指定的顶层目录（默认 `Assets/Resources`）。
3. 输出目录：默认 `Assets/StreamingAssets/EncryptedAssets`。
4. 扩展名过滤：留空加密全部，或填 `png;jpg;bundle`。
5. 点击“一键加密并生成完整性清单”（也可只加密或只生成清单）。

输出保留文件在 `Assets` 下的相对路径并追加 `.bytes`，例如：

```
Assets/待加密素材/插画/序章.png
→ Assets/StreamingAssets/EncryptedAssets/待加密素材/插画/序章.png.bytes
```

目录名使用 ASCII，是为了避开 Android 上 `jar:` URL 的转义问题。相对路径中的中文文件名通常也能工作，但建议在目标机型上验证；如果遇到读取失败，把文件名改成 ASCII 再加密一次即可。

**必须把原始素材从构建中移除**：删掉源文件，或确保它没有被场景、Prefab、Resources、Addressable 引用。否则 AssetStudio 仍能从 `resources.assets` / 场景文件里直接导出原图。

### 4. 生成完整性清单

点击“一键加密并生成完整性清单”，或单独点击“仅生成完整性清单”。每次增删改加密资源后都要重新生成，否则运行时哈希校验会失败。

### 5. 在代码里加载

图片（Android 必须用协程版本）：

```csharp
using System.Collections;
using UnityEngine;
using UnityEngine.UI;

public class 加载加密插画 : MonoBehaviour
{
    [SerializeField] private Image 目标;

    private IEnumerator Start()
    {
        yield return 加密资源.加载图片协程(
            "待加密素材/插画/序章.png.bytes",
            贴图 => 目标.sprite = Sprite.Create(
                贴图, new Rect(0, 0, 贴图.width, 贴图.height), new Vector2(0.5f, 0.5f)),
            错误 => Debug.LogError("[资源] " + 错误));
    }
}
```

AssetBundle：

```csharp
yield return 加密资源.加载资源包协程(
    "待加密素材/包/第一章.bundle.bytes",
    包 =>
    {
        var 预制体 = 包.LoadAsset<GameObject>("Chapter1");
        Instantiate(预制体);
        // 用完记得 包.Unload(false)
    },
    错误 => Debug.LogError("[资源] " + 错误));
```

### 6. 填写 APK 签名指纹

```bash
keytool -printcert -jarfile 你的.apk
```

把输出里的 `SHA256:` 去掉冒号、转小写，填入 `安全配置.期望APK签名`。留空则跳过该项校验。

### 7. 构建并检查

构建结束后看 Console：

- 是否提示“未生成资源密钥”
- 是否提示仍在用 Mono 后端
- 是否提示未填写 APK 签名指纹

最后在真机上跑一遍，确认没有误报（尤其定制 ROM / 开启 Xposed 的测试机）。

## 四、配置说明（安全配置.cs）

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `期望APK签名` | 空 | APK 证书 SHA-256；空 = 不校验 |
| `启用正版校验` | true | `Application.genuine`，仅 Android / iOS |
| `启用反调试` | true | Frida / Xposed / TracerPid / 托管调试器 |
| `启用资源完整性校验` | true | 载入清单并逐文件核对 SHA-256 |
| `响应方式` | 1 | 0 只记录 / 1 禁用加密资源 / 2 退出 |
| `首次检测延迟` | 1.5 秒 | 避开开场加载 |
| `检测间隔` | 20 秒 | 重复检测节奏 |

响应方式为 1 时，检测到异常会把 `加密资源.已禁用` 置为 true，后续所有加密资源加载都会抛异常。也可以在启动时订阅：

```csharp
安全核心.检测到异常 += 原因 => Debug.LogWarning("安全提示：" + 原因);
```

## 五、这套方案防不住什么

必须明确，避免产生错误的安全感：

1. **内存转储**：Frida、GameGuardian 可以在解密后 dump 贴图或资源包。任何“运行时必须解密”的方案都无法阻止。
2. **`global-metadata.dat` 转储**：本方案没有修改 Unity 引擎，Il2CppDumper 仍可能还原类名和方法名。要对抗它，需要 metadata 加密或商业加固。
3. **场景 / Prefab / Resources 里直接引用的资源**：不在本方案保护范围内，AssetRipper 可以直接还原整个工程结构。
4. **已 root 的定制环境**：可以绕过 maps 扫描、改端口、隐藏 TracerPid。检测只能提高门槛。
5. **Windows EXE**：`Application.genuine` 不可用；EXE 还面临直接 patch。建议配合代码签名、商业壳（VMProtect / Themida 等）和 IL2CPP。
6. **误报**：部分定制 ROM、企业设备管理、无障碍工具可能触发注入特征。上线前需要在目标机型验证，或把响应方式设为 0 先观察日志。

## 六、进阶加固建议

按投入产出排序：

1. **换用加固/加密方案**：FairGuard、JikGuard、网易易盾、LIAPP、Virbox、DexGuard/iXGuard 等，提供 `global-metadata.dat`、`libil2cpp.so`、AssetBundle 和 Mono DLL 的加密与反调试。
2. **把解密下沉到原生插件**：用 C++ 写 `.so` / `.dll` 做密钥持有和解密，C# 只调用接口，避免密钥和算法完整暴露在托管程序集里。
3. **图片隐水印**：给每份分发的素材写入不可见用户标识，泄露后可追溯来源。这通常比“防提取”更实用。
4. **资源分片 + 按需解密**：不要一次性把整包明文留在内存；关卡切换时卸载并清空引用。
5. **构建机隔离密钥**：`密钥~` 只存在构建机，CI 通过环境变量注入；仓库里只保留加密后的资源和拆分常量。
