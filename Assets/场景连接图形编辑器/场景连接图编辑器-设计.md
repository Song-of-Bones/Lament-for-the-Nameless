# 场景连接图编辑器 · 设计文档

目标：把“窗口管理 + 异步窗口 ID 数据库”从 Inspector 列表升级为**一张可读、可编辑的场景连接图**。
每个场景是一张小卡片，卡片内列出按钮/组件，连线指向它打开或跳转到的场景；也可以直接在图上拉线，把新按钮接到目标场景，自动写回组件与数据库。

---

## 1. 设计目标

### 必须做到

1. 打开一个编辑器窗口，看到 **Build Settings 中所有场景** 的卡片布局。
2. 每张卡片内显示：
   - 场景名、Build index、场景角色（login/lobby/settings/gameplay/…）；
   - 场景内所有 **连接源**：
     - `UIMenuButton`（打开窗口ID + 窗口是否为跳转 + 点击结束）；
     - `NovelEntryPoint`（runtimeScene，直接切场景）；
     - 其他带 `Button.onClick` 持久监听的对象（只读展示，标记为 event）；
   - 场景内 `WindowDatabase` 的 **窗口定义**（configs / jumpConfigs）。
3. 连线表达真实关系，并区分：
   - `async`：Additive 加载窗口场景（`WindowDatabase.configs`）；
   - `jump`：Single 跳转场景（`WindowDatabase.jumpConfigs`）；
   - `direct`：`NovelEntryPoint.runtimeScene` 直接切场景；
   - `event`：UnityEvent 调用，目标未知（虚线，只读）。
4. 从按钮行的输出端口拖到目标场景卡片，创建/替换连接，并写回：
   - `UIMenuButton.打开窗口ID`、`窗口是否为跳转`；
   - `WindowDatabase.configs/jumpConfigs` 的 `{id, sceneName}`；
   - 或 `NovelEntryPoint.runtimeScene`。
5. 右键菜单覆盖画布、卡片、按钮行、连线四类对象。
6. 布局持久化：卡片位置、折叠状态、过滤条件保存到项目内 JSON。
7. 校验可视化：目标场景不在 Build、ID 未配置、重复 ID、场景缺失、循环跳转。

### 非目标

- 不重写运行时 `SettingsWindowManager` 的加载逻辑（现有 Additive/Single 行为保留）。
- 不把 `WindowDatabase` 改成 ScriptableObject（继续做场景 MonoBehaviour，避免破坏现有引用）。
- 不做运行时可视化（这是 Editor-only 工具）。

## 2. 现状与数据流

```
UIMenuButton.确认()
  ├─ 打开窗口ID 非空 → SettingsWindowManager.打开设置(id, 窗口是否为跳转)
  │     ├─ false → WindowDatabase.GetAsyncSceneName(id) → LoadSceneAsync(scene, Additive)
  │     └─ true  → WindowDatabase.GetJumpSceneName(id)  → LoadSceneAsync(scene, Single)
  └─ 点击结束 UnityEvent → 例如 NovelEntryPoint.StartNewGame()
        └─ SceneManager.LoadSceneAsync(runtimeScene)   // Single
```

关键类型：

| 类型 | 位置 | 关键成员 |
|---|---|---|
| `WindowDatabase` | `Assets/WindowDatabase.cs` | `configs`、`jumpConfigs`，`WindowConfig{id, sceneName}` |
| `SettingsWindowManager` | `Assets/Animation/Scripts/AsyncWindowManager.cs` | `打开设置(id, 是跳转)` |
| `UIMenuButton` | `Assets/Animation/Scripts/MenuButtonAnimator.cs` | `打开窗口ID`、`窗口是否为跳转`、`点击结束` |
| `NovelEntryPoint` | `Assets/VisualNovel/Integration/NovelEntryPoint.cs` | `runtimeScene` |
| `SettingsWindow` | 窗口场景内 | `打开(OnWindowClosed)` |

**连接源的真实身份** = 场景路径 + 对象层级路径 + 组件类型 + 字段/方法。
写回时必须按这个身份定位对象，不能只按名字。

## 3. 图模型

### 3.1 节点

```csharp
class SceneGraphScene {
    string scenePath;        // Assets/Scenes/Lobby.unity
    string sceneName;        // Lobby
    int buildIndex;          // -1 = 不在 Build
    string role;             // login/lobby/settings/gameplay/novel/other
    Vector2 cardPosition;    // 布局持久化
    bool collapsed;
    List<SceneGraphSource> sources;
    List<SceneGraphWindowDef> windowDefs;
    List<SceneGraphDiagnostic> diagnostics;
}

class SceneGraphSource {
    string objectPath;       // Canvas/菜单/开始游戏
    SourceKind kind;         // UIMenuButton / NovelEntryPoint / ButtonEvent
    string displayName;      // 开始游戏
    string windowId;         // UIMenuButton.打开窗口ID（可为空）
    bool isJump;             // UIMenuButton.窗口是否为跳转
    string runtimeScene;     // NovelEntryPoint.runtimeScene
    string eventTarget;      // Button.onClick 目标（只读）
    EdgeMode mode;           // async/jump/direct/event/none
    string targetSceneName;  // 解析后的目标
    bool resolved;           // 目标能在 Build/资产中找到
}

class SceneGraphWindowDef {
    string id;
    string sceneName;
    bool isJump;             // configs=false, jumpConfigs=true
    string ownerObjectPath;  // WindowDatabase 所在对象
}
```

### 3.2 边

```csharp
class SceneGraphEdge {
    string sourceScenePath;
    string sourceObjectPath;   // 为空表示场景级窗口定义
    string sourceKind;         // UIMenuButton / NovelEntryPoint / WindowDatabase
    string windowId;
    EdgeMode mode;             // async/jump/direct/event
    string targetScenePath;    // 解析后的资产路径
    bool resolved;
}
```

### 3.3 边的解析规则

| 源 | 模式 | 目标解析 |
|---|---|---|
| `UIMenuButton` + `打开窗口ID` | `窗口是否为跳转` | `WindowDatabase` 对应列表查 `id` |
| `NovelEntryPoint` | `direct` | `runtimeScene` → `Assets/**/{name}.unity` |
| `Button.onClick` 持久监听 | `event` | 尝试匹配方法名/目标类型，解析不到则虚线 |
| `WindowDatabase` 配置 | `async`/`jump` | `sceneName` |

**目标场景解析**：先 Build Settings 精确路径；再按场景名在 `Assets` 下唯一匹配；多匹配 → 诊断歧义。

## 4. 窗口布局与卡片

```
┌──────────────────────────────────────────────────────────────┐
│ 工具栏：[扫描] [保存布局] [自动布局] [应用更改]  搜索…  图例  │
├──────────────┬───────────────────────────────────────────────┤
│ 左侧详情面板 │  GraphView 画布（缩放/平移/框选/迷你地图）      │
│ 选中对象属性 │                                               │
│ 校验列表     │   ┌─ Lobby ──────────────┐   ┌─ Settings ──┐ │
│              │   │ 按钮 开始游戏  ●──┐  │──▶│ 设置窗口     │ │
│              │   │ 按钮 继续游戏  ●──┼──┘   └─────────────┘ │
│              │   │ 入口 Novel     ●──┼──▶ NovelRuntime      │
│              │   │ 窗口 def: id→场景 │                       │
│              │   └───────────────────┘                       │
└──────────────┴───────────────────────────────────────────────┘
```

### 4.1 卡片结构

- **标题栏**：场景名 + `Build #index` + 角色色条；折叠按钮；双击打开场景。
- **入口区**（可选）：`NovelEntryPoint` 行，带输出端口。
- **按钮区**：每个 `UIMenuButton` 一行：
  - 左侧状态点（绿=已解析，黄=ID 未配置，红=目标缺失，灰=未连接）；
  - 按钮名；
  - 模式徽标：`异步` / `跳转` / `直接` / `事件`；
  - 目标场景名；
  - 右侧输出端口。
- **窗口定义区**：`WindowDatabase` 的 `id → sceneName` 列表，每行带输出端口（作为“场景级连接”）。
- **输入端口**：卡片左侧一个，表示“这个场景可以作为目标”。

### 4.2 卡片尺寸与折叠

- 默认宽 320，高度随行数增长（上限 520，超出滚动）。
- 折叠后只显示标题行 + 连接计数。
- 卡片颜色按角色：login 蓝、lobby 紫、settings 灰、gameplay 绿、novel 橙、other 灰。

## 5. 交互设计

### 5.1 画布

- 缩放：`ContentZoomer`（0.1x–2x）。
- 平移：`ContentDragger` / 中键拖拽。
- 框选：`RectangleSelector`。
- 迷你地图：`MiniMap`，右下角。
- 双击空白：打开“添加场景卡片”搜索窗。
- 工具栏“自动布局”：按 Build index 网格；或按连接 BFS 从左到右分层。

### 5.2 拖线

1. 从按钮行/入口行/窗口定义行的输出端口按下。
2. 画布高亮所有可作为目标的场景卡片输入端口。
3. 拖到目标卡片：
   - 若源是 `UIMenuButton`：弹出小菜单选择 `异步窗口` / `跳转场景`（默认按当前 `窗口是否为跳转`）。
   - 若源是 `NovelEntryPoint`：直接写 `runtimeScene`。
   - 若源是 `WindowDatabase` 配置：更新 `sceneName`。
4. 拖到空白：弹出场景选择器（Build Settings 场景列表 + 搜索），选择后同上。
5. 拖到已有连线：替换目标。
6. `Esc` 取消；`Ctrl+Z` 撤销（见 6.3）。

### 5.3 右键菜单

#### 画布空白

- `扫描 / 刷新全部`
- `自动布局` → 子菜单：`按 Build index`、`按连接层级`
- `保存布局`
- `添加场景卡片` → Build Settings 中尚未加入图的场景
- `全部展开`
- `全部折叠`
- `显示未连接按钮`（勾选）
- `显示 event 连线`（勾选）
- `图例`
- `打开布局文件`

#### 场景卡片

- `打开场景`（Single）
- `以 Additive 打开`
- `设为当前编辑场景`
- `刷新此场景`
- `添加窗口配置…`（弹窗：ID + 目标场景 + 异步/跳转）
- `在此场景添加连接…`（选择场景内 UIMenuButton/NovelEntryPoint）
- `从图中移除`（仅移除卡片，不删场景）
- `在 Project 中定位场景资产`
- `复制场景路径`

#### 按钮行 / 输出端口

- `编辑连接…`（弹窗：ID、模式、目标场景）
- `切换为 异步窗口`
- `切换为 跳转场景`
- `清除连接`
- `复制窗口 ID`
- `在场景中定位对象`（选中 + SceneView 框选）
- `从 WindowDatabase 删除该 ID`
- `只读原因`（event 行显示为什么不可编辑）

#### 连线

- `切换 异步/跳转`
- `编辑目标场景…`
- `删除连接`
- `定位源对象`
- `定位 WindowDatabase 配置`

#### 输入端口 / 目标卡片

- `作为异步窗口目标`
- `作为跳转目标`
- `创建新按钮连接到此场景…`（选择源场景 + 按钮）

### 5.4 工具栏

- **扫描/刷新**：重新读取所有 Build 场景。
- **保存布局**：写 JSON。
- **自动布局**：重排。
- **应用更改**（草稿模式时）：批量写回。
- **搜索框**：按场景名/按钮名/ID 过滤，命中卡片高亮。
- **过滤**：全部 / 仅已连接 / 仅有错误 / 仅未连接。
- **图例**：模式颜色 + 状态颜色。
- **帮助**：打开本设计文档。

### 5.5 左侧详情面板

选中卡片/按钮/连线时显示：

- 场景：路径、Build index、角色、连接统计。
- 按钮：对象路径、组件类型、`打开窗口ID`、`窗口是否为跳转`、目标、错误。
- 连线：源/目标、模式、数据库条目位置。
- 操作按钮：定位、编辑、删除。

## 6. 写回与跨场景编辑

### 6.1 写回目标

| 操作 | 写回位置 |
|---|---|
| 按钮 → 目标场景（async） | `UIMenuButton.打开窗口ID = id`；`窗口是否为跳转 = false`；`WindowDatabase.configs` 添加/更新 `{id, sceneName}` |
| 按钮 → 目标场景（jump） | 同上，`窗口是否为跳转 = true`；写 `jumpConfigs` |
| NovelEntryPoint → 目标场景 | `NovelEntryPoint.runtimeScene = sceneName` |
| 窗口定义 → 目标场景 | `WindowDatabase.configs/jumpConfigs` 的 `sceneName` |
| 删除连接 | 清空 `打开窗口ID` 或移除数据库条目（弹窗确认） |

### 6.2 ID 生成规则

- 默认：`{sourceSceneName}_{buttonObjectName}`，转小写下划线，去重。
- 若源已有 `打开窗口ID`，复用。
- 目标场景已有同 ID 条目且指向不同场景 → 黄灯提示，允许覆盖或改名。
- ID 在同一列表内必须唯一；async 与 jump 可重复（现有设计允许）。

### 6.3 Undo 与保存

- 每次写回：
  1. `Undo.RegisterCompleteObjectUndo` / `Undo.RecordObject`；
  2. 修改 `SerializedObject`；
  3. `EditorUtility.SetDirty`；
  4. `EditorSceneManager.MarkSceneDirty`；
  5. 不自动保存场景，除非用户点“保存场景”或工具栏“应用并保存”。
- 图编辑器内提供 **草稿模式**（默认开）：
  - 拖线只改内存模型；
  - “应用更改”批量写回；
  - 关闭窗口时提示未应用更改。
- 也可切换 **即时模式**：每次拖线立即写回。

### 6.4 跨场景打开/保存

写回可能涉及多个场景（源场景 + `WindowDatabase` 所在场景）。

`SceneEditSession` 负责：

1. 记录当前活动场景与已打开场景集合。
2. 对每个待修改场景：
   - 已打开 → 直接修改；
   - 未打开 → `OpenScene(path, Additive)`，修改后 `SaveScene`，再 `CloseScene`。
3. 若场景有未保存修改 → 弹窗：`保存 / 放弃 / 取消`。
4. 恢复原活动场景与选择。
5. 所有场景操作前后 `AssetDatabase.StartAssetEditing/StopAssetEditing`（可选）。

**禁止**在 `OpenScene` 时触发 `Awake` 副作用：现有组件没有 `ExecuteInEditMode`，安全；若未来新增，需要检查。

### 6.5 批量写回顺序

1. 先写 `WindowDatabase`（确保 ID 存在）。
2. 再写 `UIMenuButton`/`NovelEntryPoint`（引用 ID/场景）。
3. 最后保存场景。
4. 任一步失败 → 回滚内存模型，保留场景 Undo。

## 7. 布局与持久化

### 7.1 布局文件

`Assets/场景连接图形编辑器/SceneGraphLayout.json`

```json
{
  "version": 1,
  "nodes": {
    "Assets/Scenes/Lobby.unity": { "x": 120, "y": 80, "collapsed": false },
    "Assets/Scenes/Settings.unity": { "x": 520, "y": 80, "collapsed": false }
  },
  "view": { "x": 0, "y": 0, "scale": 1 },
  "filters": { "showUnconnected": true, "showEvents": true }
}
```

- 使用 `JsonUtility`（支持字典需包一层列表）或 `Newtonsoft`（项目已有 `Codely.Newtonsoft.Json`？不依赖）。
- 更稳：`List<NodeLayout>{scenePath,x,y,collapsed}`，避免字典序列化问题。

### 7.2 自动布局

- **Build index 网格**：每行 4 张，间距 380×260。
- **连接层级**：以入口场景（Login/Lobby）为第 0 层，BFS 目标场景；async 边不增加层级（窗口叠加），jump/direct 增加层级。

### 7.3 布局写入时机

- 拖动卡片结束（`graphViewChanged` 的 `MoveElements`）。
- 折叠/展开。
- 工具栏“保存布局”。
- 窗口关闭时自动保存。

## 8. 校验与诊断

`SceneGraphValidator` 产出 `List<Diagnostic>`：

| 级别 | 规则 | 显示 |
|---|---|---|
| Error | 目标场景不在 Build Settings | 连线红色 + 卡片角标 |
| Error | 目标场景资产不存在 | 红色 |
| Warning | `UIMenuButton.打开窗口ID` 非空但数据库无对应 ID | 黄色 |
| Warning | 同一列表内 ID 重复 | 黄色 |
| Warning | 场景名多匹配 | 黄色 |
| Info | 未连接的按钮 | 灰色 |
| Info | 循环跳转（jump/direct 有向环） | 紫色虚线 + 面板提示 |

点击诊断项 → 定位对应卡片/按钮/连线。

## 9. 技术选型

### 选用 Unity GraphView

已验证当前 Tuanjie 6000.6 可用：

- `UnityEditor.Experimental.GraphView.GraphView`
- `Node`、`Port`、`Edge`、`EdgeConnector<Edge>`
- `ContentZoomer`、`ContentDragger`、`SelectionDragger`、`RectangleSelector`
- `MiniMap`、`SearchWindow`
- `graphViewChanged`（移动/删除/连线）
- `RegisterCallback<ContextualMenuPopulateEvent>`

优点：缩放/平移/框选/连线/迷你地图/搜索窗全部现成，接近 Shader Graph 的交互质量。
风险：命名空间标记 `Experimental`，但 Unity 6 仍随编辑器提供；升级时需回归测试。

### 备选

- **UI Toolkit 自绘**：可控但工作量大（连线命中、缩放、框选、拖拽都要写）。
- **IMGUI 自绘**：兼容性最好，但交互体验差，不适合“大画布”。

结论：**GraphView**。

### 关键 API 草图

```csharp
var graphView = new GraphView {
    style = { flexGrow = 1 }
};
graphView.AddManipulator(new ContentDragger());
graphView.AddManipulator(new SelectionDragger());
graphView.AddManipulator(new RectangleSelector());
graphView.AddManipulator(new ContentZoomer());
graphView.SetupZoom(0.1f, 2f);
graphView.Add(new MiniMap());
graphView.graphViewChanged += OnGraphChanged;

graphView.RegisterCallback<ContextualMenuPopulateEvent>(evt => {
    evt.menu.AppendAction("扫描 / 刷新全部", _ => ScanAll());
    evt.menu.AppendAction("自动布局", _ => AutoLayout());
    // ...
});
```

端口与连线：

```csharp
var output = Port.Create<Edge>(Orientation.Horizontal, Direction.Output, Port.Capacity.Multi, typeof(bool));
output.portName = "打开";
output.AddManipulator(new EdgeConnector<Edge>(new EdgeDragHelper<Edge>(...)));
```

> 实际实现时优先用 `Port` 自带拖拽 + `graphViewChanged` 捕获 `Edge` 创建/删除；若 GraphView 版本差异导致 `EdgeConnector` 构造签名变化，则用 `Port` 的默认 `EdgeDragHelper`。

## 11. 分阶段实现

### P1 · 只读图（先看得见）

- 扫描 Build Settings 场景；
- 卡片 + 按钮行 + 窗口定义行；
- 解析 async/jump/direct/event 连线；
- 自动布局 + 迷你地图 + 缩放/框选；
- 校验面板；
- 右键：打开场景、定位对象、复制 ID、刷新、自动布局；
- 布局 JSON 保存/恢复。

**验收**：打开窗口即可看到 Lobby → Settings/NovelRuntime 的真实连接，点击可定位。

### P2 · 可编辑（能拉线）

- 输出端口拖到目标卡片；
- 异步/跳转选择；
- 写回 `UIMenuButton`、`NovelEntryPoint`、`WindowDatabase`；
- Undo + 场景 dirty + 保存；
- 右键：编辑连接、切换模式、删除、添加窗口配置；
- 草稿模式 + 应用更改。

**验收**：新建一个按钮 → 图上拉线到 Settings → 场景里 `打开窗口ID` 与数据库条目自动生成 → 运行时点击能打开。

### P3 · 打磨

- 搜索/过滤/循环检测；
- 复制粘贴节点/连线（GraphView 序列化）；
- 批量应用 + 冲突提示；
- 导出 Mermaid/JSON 文档；
- 键盘快捷键（Delete、F 聚焦、Ctrl+S 保存布局）。

## 12. 验收标准

1. 图中场景数量 = Build Settings 场景数量（可过滤）。
2. 每个 `UIMenuButton` 都有一行；`打开窗口ID` 能解析到目标场景的连线为绿色。
3. `NovelEntryPoint` 显示 direct 连线。
4. `WindowDatabase` 的每个 config/jumpConfig 都有对应连线或“孤立配置”标记。
5. 拖线写回后，重新扫描结果一致；组件字段与数据库条目同时更新。
6. 断开/删除连线后，组件字段清空或数据库条目移除（按确认弹窗）。
7. 布局重启编辑器后保持。
8. 所有修改可 Undo；场景保存前有 dirty 标记。

## 13. 风险与边界

| 风险 | 处理 |
|---|---|
| GraphView 是 Experimental，版本升级可能改签名 | 隔离在 `Graph/` 层，写适配层；升级时只改适配层 |
| 跨场景打开/保存触发副作用 | 现有组件无 ExecuteInEditMode；写回前检查 `EditorSceneManager.SaveCurrentModifiedScenesIfUserWantsTo` |
| 场景名重复 | 解析为多匹配时标黄，要求用户选路径 |
| ID 重复（async/jump 允许重复） | 仅在同一列表内校验唯一 |
| 直接改场景导致用户未保存内容丢失 | 草稿模式 + 应用前提示 + Undo |
| 大型项目卡片过多 | 过滤/折叠/搜索/迷你地图；分页可用 Build index 分组 |
| `Button.onClick` 无法可靠解析参数 | 标记为 event 只读，不自动写回 |
